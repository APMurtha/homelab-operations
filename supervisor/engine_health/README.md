# Four stored engine health results

The two oneshots use the existing operations-v1 receipt schema. They do not run a health check. The timer triggers the publisher. Its Wants/After dependency runs the reader first, including when the previous run failed.

systemd 253 or later opens the local engine socket and supplies one connected descriptor named engine. The dedicated system account has a locked login, no Docker group and no engine path access from its mount namespace. Compile request.c with `cc -O2 -Wall -Wextra -Werror -static -o request request.c`. The helper accepts no arguments. It writes two compiled-in rounds of four exact HTTP GETs, shuts down the write side, and closes extra descriptors before executing the isolated parser. The parser can only consume the already-requested responses. Its service denies socket creation and connect, has no capabilities, and discards stdout/stderr. Bound the response size and runtime; never persist inspect payloads or health output.

Install the root-owned executable and acquire.py, release.py, ops_protocol.py, dispatcharr_project.py and dispatcharr_monitor_fields.py in /opt/samwise-engine-health. Keep the scripts/modules 0644 and executable 0755. Use the merged operations-v1 sources for the three shared modules. Install the two enforcing AppArmor profiles and packaged systemd units. Stage with the timer disabled and the publisher directed to a scratch mount. Test known-good, stale, changed identity, missing source and invalid permission cases. Independently compare the two rounds with fixed-name engine reads before and after, including probe nanoseconds. Inspect the actual output metadata and the effective service restrictions before enabling.

The reader atomically replaces one 0600 batch in its private 0700 runtime directory. It retains acquisition times and selected health fields only. The publisher runs under a separate profile as root with the existing observation group, read-search capability, no network, and write rules for only four names and atomic temporary files. It checks the batch's custodian, mode, link count, timestamps, schema and per-container invariants. A missing or invalid batch withdraws all four files, an invalid individual record withdraws the dependent file, and an old completed probe keeps its original time and expires at 60 seconds. If the publisher itself stops, the collector enforces expiry independently. The 64 MiB reader and publisher limits apply separately. A short-lived unit can be unloaded after exit; hold systemd Manager.RefUnit during a bounded comparison to retain CPU accounting.

Before replacing the collector, preserve its installed protocol, collector, launcher and existing relay projector/timer with hashes and metadata. Install the protocol first, then atomically replace the collector. Confirm existing scope and healthy baseline. Enable only samwise-engine-health-publish.timer after the approved comparison passes. Compare several actual timer cycles with the original engine observations.

To withdraw this rollout, disable and stop this timer, stop only its read and publish oneshots, remove only the four new evidence files and private batch, and restore the preserved collector then protocol with original hashes/metadata. Verify continuity of the relay/playlist writer and observer restrictions. Only then remove the new units, AppArmor profiles, code and dedicated account if authorized. Keep the existing observations directory, relay timer, SSH enrollment, and supervisor state. A live operations-v1 issue requires its own authorization.
