## Private source contract

The candidate translator is a separate local file-only process. It has no SSH command, Docker/API client, subprocess, monitoring credentials or input supplied by the issue author. The SSH collector still has only its fixed observation directory and closed response vocabulary.

An approved custodian may export already captured evidence to **/run/samwise-monitor-inputs**. Each file is a single root-owned regular file, 0400/0440/0600/0640, at most 32 KiB, no symlinks, hardlinks or group/world write. Use 0700 root directories for raw inputs and policy. Write by atomic replacement. Each object has exactly source, target (rivendell-dispatcharr), boot_id (local canonical UUID at acquisition), sampled_ns (UTC epoch nanoseconds at acquisition) and evidence. For composite data use the earliest actual measurement, including relay generation, namespace and enforcement samples. Capture in one coherent interval and verify container identity/start before and after acquisition. Reject changes, partial captures, unsuccessful API queries, truncated pages or unknown acquisition times. A file timestamp is only a cross-check. Re-exporting must preserve the original measurement times. The translator trusts the custodian and cannot authenticate the truth of a fabricated root-owned measurement.

- **backend.json, gateway.json, vpn-container.json, jellyfin.json** use engine-health-v1. In an already authorized monitoring process, engine_fields selects only the required fields of an existing engine observation. It discards configuration, environment and probe output. Confirm the four fixed names and actual health-check coverage before enrollment.
- **celery.json** uses dispatcharr-pong-v1. Run the existing pinned receipt reader on the complete receipt in the custodian boundary. Pass only its terminal celery record to celery_fields, with the container identity at acquisition. Preserve the time of that stage. Never combine worker flags from different probes. Without a current validated capture the result expires. No collector-triggered or scheduled Celery ping is included.
- **protection.json** uses kernel-policy-v1. Use the native verifier's existing observation semantics. Hash canonical(live_table) with rules_digest. Separately provision **/etc/samwise/dispatcharr-evidence/enrollment.json** containing policy_sha256 and rules_sha256 from the reviewed policy and canonical(expected_table(policy)). Both sides use the pinned permanent-streaming/contracts.py canonical function. Preserve rule order. Match generation before/after, grant generation, relay's observed guard generation and namespace identities. The input schema and exact fields are in protection and the fixture. For VPN, dns_restricted covers both the resolver rules and the workloads' actual resolver configuration. A null grant requires explicit, successfully observed withdrawal. Missing source data is unavailable. Do not run the broad production verifier as a projector.
- **livetv.json** uses jellyfin-livetv-v1. Feed livetv_fields a complete inventory from LiveTv/Channels and the bounded current LiveTv/Programs response filtered to the enrolled channel ID and time. Use an already authorized authenticated custodian. A complete empty inventory can establish absent. A complete empty program response for a present channel can establish empty. A missing program response leaves guide unavailable. The field selector drops titles, URLs, session data and unrelated channels. The collector receives only statuses.

dispatcharr_project.py opens fixed sources without following links, enforces ownership/modes and reads each once. It publishes root-owned 0640 receipts by atomic replacement, preserving acquisition time as mtime. Malformed or missing inputs invalidate only the dependent output files. The reader checks exact schema, source ID, observation name, mtime and bounded validity interval on every read. Future or contradictory data yields unavailable. Expired well-formed data yields stale even if the translator stops. Source IDs identify the contract selected by the custodian. The protocol returns only enums to Bag-End. A writer holding root or a compromised monitoring principal is outside this trust boundary.

## Controlled deployment and rollback

1. Obtain review of the PR commit and a separate owner grant specifying the source custodian, enrolled topics, schedule and allowed host changes. No recurring fresh exports for the nine topics were confirmed during inventory. First validate real source fields, timestamp resolution, authority and collection overhead. If existing monitoring cannot supply a topic, leave it unavailable. A new privileged producer, service access, token or new live sampling needs its own reviewed design and approval.
2. Under that grant, record digests, metadata, confinement and health of the installed collector, protocol, existing projector, timers and relay output. Preserve the **installed** collector/protocol pair and their metadata in a root-only rollback directory. Compare candidate hashes against the approved Git revision using git show and sha256sum. Abort on unexpected drift. Retain the current Bag-End binary, SQLite state, label, SSH keys and existing timers.
3. Stage the candidate collector/protocol together in a root-only scratch directory with the current isolated launcher. Use root-owned synthetic fixtures and verify both relay and new states under the deployed AppArmor/seccomp rules. Verify the forced account cannot write files, traverse raw source directories, open sockets or read credentials. Abort on a permission exception or confinement regression. No broadening of SSH/AppArmor permissions is required by the wire protocol.
4. Install only after those checks. Use the existing trusted collector path and its existing file metadata. Replace the protocol first (additive functions), then the collector by atomic rename. Separately stage the projector and protocol under /opt/samwise-dispatcharr-evidence, root:root 0755 directory and 0644 code. The monitor field selectors belong only with the authorized custodian. The separate translator invocation is /usr/bin/python3 -IB /opt/samwise-dispatcharr-evidence/dispatcharr_project.py. Run one instance at a time, primary group equal to the existing observation read group. Constrain it to fixed input/policy files, boot ID, interpreter and its own output filenames/temp prefix; deny sockets, subprocess execution after launch, credentials and media paths. Verify an output is root:observation-group 0640. Do not replace the existing relay/playlist publisher. Review confinement and unit files separately before installing any new service or timer.
5. Validate each authorized feed against a private reference observation, checking freshness, instance, rules and expiry. Test stopped exporter/expired guide on scratch fixtures. Abort on an unexplained positive, ambiguous provenance, public data outside enums, changed baseline or any need for wider privileges. Obtain **separate live diagnostic approval** after verifying the baseline again.
6. Roll back by stopping only the separately approved new translator schedule, withdrawing only its enrolled export feeds, and removing only its nine named output files. Restore the original collector first and then the original protocol, atomically with their saved ownership and modes. Verify their digests, original relay writer/mtime and existing timer health. Retain supervisor state, SSH restrictions and existing relay/playlist files. Production media and bridge lifecycle operations are outside this procedure.
