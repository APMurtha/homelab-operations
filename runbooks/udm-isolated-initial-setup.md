# UDM Pro Max isolated initial setup

Status: **READY TO USE; execution not yet verified**. The owner reports that the UDM Pro Max has arrived. This checklist changes only the new, isolated UDM. `anduin`, the ARRIS Surfboard, `osgiliath`, `lothlorien` and all adopted devices remain in production. Follow the [migration plan](../docs/udm-pro-max-migration.md) for the later gateway cutover; the eventual UDM-to-`osgiliath` link is **one Cat6 cable**, with no LAG.

## Boundary before power-on

- [ ] Place the UDM on stable power and connect **one setup laptop to a UDM LAN port**. Leave every UDM LAN port disconnected from `osgiliath`, APs, Proxmox, the NAS and any other production LAN. Do not move the ARRIS Ethernet/coax or an OPNsense cable.
- [ ] Choose the update path: an independent Internet source into **UDM WAN**, or a known ordinary client access port on the existing network into **UDM WAN only**. The latter makes the UDM a temporary downstream client of OPNsense; it requires no production configuration change but will obtain a normal upstream lease. Do not use a port whose role/profile is uncertain. Record the temporary upstream subnet and ensure it does not overlap the UDM's current LAN subnet.
- [ ] If neither safe update path is available, proceed with local setup if the wizard permits it and **defer online updates**. Do not move the Comcast modem to make the setup wizard pass. UniFi supports local web setup; online updates require Internet, while offline updating is a separate advanced procedure. [Setup](https://help.ui.com/hc/en-us/articles/4416276882327-How-to-Set-Up-UniFi), [updates](https://help.ui.com/hc/en-us/articles/7605005245975-UniFi-Updates).

## Initialize and update the isolated console

- [ ] Power on the UDM. From the directly connected laptop, open the local address shown by the console/setup wizard. Confirm the displayed model is **Dream Machine Pro Max**. Complete initial setup with your own UI/local administrator account; enter credentials only in the device UI. Record the assigned console name, UniFi OS version, Network application version and current LAN/WAN subnets in private notes. [UniFi setup](https://help.ui.com/hc/en-us/articles/4416276882327-How-to-Set-Up-UniFi).
- [ ] If a safe temporary WAN is present, confirm the UDM alone has Internet, DNS and time sync. Use **Settings → Control Plane → Updates** to install current stable/Official UniFi OS and Network updates, allowing each update to finish and the local UI to return. Verify versions and local login after reboot. Leave production switching and wireless untouched. [UniFi updates](https://help.ui.com/hc/en-us/articles/7605005245975-UniFi-Updates).
- [ ] Keep the temporary WAN on the UDM only for setup/update. **Disconnect it before creating any UDM LAN/VLAN subnet that overlaps that WAN's upstream subnet.** If the source was OPNsense, confirm the temporary client link is down; do not renew or change the OPNsense lease.
- [ ] Save a private UDM backup or recovery record after initial setup. Keep backups, recovery codes, credentials, public addresses, MACs and serials outside Git. Confirm local login still works with the UDM WAN unplugged. [UniFi backups](https://help.ui.com/hc/en-us/articles/360008976393-Backups-and-Migration-in-UniFi).

## Stage configuration without migrating devices

- [ ] In `lothlorien`'s UI, manually record the **Network application version, site count, current backup availability and `osgiliath`/`ithil` adoption state**. Download a current Network backup (`.unf`) to private storage. Do not stop `lothlorien`, forget devices, change inform host, or adopt anything. UDM Cloud Gateways include their own Network application and cannot be managed by the existing self-hosted controller. [Self-hosting](https://help.ui.com/hc/en-us/articles/34210126298775-Self-Hosting-UniFi), [backup migration](https://help.ui.com/hc/en-us/articles/360008976393-Backups-and-Migration-in-UniFi).
- [ ] Decide whether to restore that Network backup on the **isolated** UDM after checking site count and version compatibility in its UI. A restore may replace UDM Network settings; review the resulting networks, profiles and site before staging additional settings. Keep all production devices connected to `lothlorien`. If compatibility or site mapping is unclear, defer restore; it is **not a blocker for power-on or updates**. A Network backup does not include OPNsense DHCP, firewall, NAT or routes. [Backup migration](https://help.ui.com/hc/en-us/articles/360008976393-Backups-and-Migration-in-UniFi).
- [ ] With every UDM LAN port still isolated and temporary WAN disconnected if overlapping, stage only confirmed gateway settings: MGMT `10.10.10.1/24` as **untagged** for the initial cutover if the later switch check supports it; tagged VLANs 20–70 with their existing `.1/24` gateways; and reviewed DHCP scopes/options. Do not create tagged VLAN 10 management now. Do not enable unreviewed WAN forwards, VPNs or broad inter-VLAN allows. Saved Anduin rules are not a verified effective policy. See [Anduin findings](../docs/anduin-discovery-2026-11-02.md).
- [ ] From the directly connected test laptop, verify local UDM login, the intended isolated LAN gateway and a single UDM DHCP response on that **test link only**. Record which settings are staged versus still pending policy review. Export another private UDM backup after the staged configuration is stable.

## Stop point and handoff

- [ ] Leave UDM LAN **disconnected from production**, and leave ARRIS → Anduin → `osgiliath` and all existing device adoption unchanged. Do not connect the planned single Cat6 switch uplink yet. Label the UDM's staged port and power state for the later maintenance window.
- [ ] Record a short setup receipt outside secrets: date, UDM model, UniFi OS/Network versions, update result, backup/restore result, temporary WAN source and removal, staged subnets, local login test, and any setup error. Mark untested production behavior **UNKNOWN**.

If setup cannot complete, stop on the isolated UDM. The existing network should continue unchanged. Do not troubleshoot by connecting the UDM LAN to `osgiliath`, moving the ARRIS, disabling OPNsense DHCP, or adopting production devices.
