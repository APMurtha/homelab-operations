### UniFi read sequence after authenticated access is available

Use the scoped `andrew` / `andrew-network` NEST runner. Start with `unifi-access doctor --local`, then `hosts`; match the reported host name/identity to `lothlorien` before using its host ID. Run `network-info --host-id HOST_ID` for the Network version and `network-sites --host-id HOST_ID` for Network site UUIDs. With the verified site UUID, run `network-devices --host-id HOST_ID --site-id SITE_UUID`, then `network-device` for the identified `osgiliath` and `ithil` device UUIDs. These commands are bounded GETs and redact identifiers/fields in their rendered output; they do not alter adoption or port settings. Keep provider IDs and any raw responses private.

The bundled `network-device` summary includes device state, uplink device ID and port link state/speed but **does not expose per-port VLAN profile or LAG configuration**. Inspect those settings in the authenticated controller UI or another separately authorized read-only route. Record each relevant port number, native network, allowed tagged VLANs, LAG membership, LLDP neighbor, active speed and cable-label confirmation. Verify that the displayed site and device serial/model match the intended equipment before recording a port as current. If access is missing, leave these fields **UNKNOWN** rather than copying the February 2026 profile names into the target plan.
