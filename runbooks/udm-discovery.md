# Read-only discovery for the UDM Pro Max migration

Status: **PLANNED**. Commands below are proposals, not evidence they ran. Obtain each system's authorized read-only access and confirm the target before use. Run one bounded query at a time; do not export raw configuration into Git. Redact public IPs, host IDs, MACs and other sensitive values in shared notes.

| Target | Proposed read-only checks | Safety / handling |
|---|---|---|
| OPNsense `anduin` UI | System > Interfaces, Assignments, VLANs, Gateways, Routes; Firewall > Rules (all tabs, including floating), Aliases, NAT (outbound/port forward/1:1), VPN sections; Services > Kea DHCP, DNS, Unbound; System > Settings > General | UI viewing only. Avoid Apply/Save, renew/release, tests that change state. Private configuration backup later for rollback; never commit it. Record exact interface/IP, WAN DHCP/IPv6, rule order, NAT, routes, VPN listeners, DHCP pools/reservations/options and DNS. |
| OPNsense shell, if authorized | `ifconfig -a`, `netstat -rn -f inet`, `netstat -rn -f inet6`, `pfctl -sr`, `pfctl -sn`, `pfctl -s Tables`, `sockstat -4 -6 -l` | Passive status, but raw output may reveal public endpoints and internal policy; store privately. `pfctl` needs appropriate privilege; never use rule reload/flush flags. Kea/OPNsense UI or reviewed redacted export is preferred for scope/alias semantics. |
| UniFi `lothlorien` | Network About/version, site list, backup availability, Devices/adoption and inform path, Networks, WiFi, switch port profile and per-port assignments, LAGG, AP uplink and management VLAN | Read-only UI or NEST scoped `unifi-manage inspect` after local binding and authenticated target verification. An API response does not prove physical switch-port wiring. Never adopt/reprovision or change inform host during discovery. |
| Proxmox nodes | `pvecm status`, `pvesh get /nodes`, `ip -br addr`, `ip -d link show`, `bridge vlan show`, `cat /etc/network/interfaces`, `pvesm status`, `zpool status` | Passive reads; output may contain cluster/storage identifiers. Confirm all three nodes, vmbr mappings, VLAN awareness, NICs, VM/LXC placement, `moria` and gateway/DNS dependencies. No `ifreload`, migration or storage action. |
| `palantir` | Pi-hole UI settings for upstream/conditional forwarding/local records; `pihole status`; read Unbound configuration and `resolvectl status` or `/etc/resolv.conf` as applicable | Status/config reads only. Identify actual recursion/forwarding chain and firewall DNS block/redirect path. Do not flush caches or change records. |
| UNAS Pro 8 | UniFi Drive UI device/storage/network status; switch port detail; host mount tables (`findmnt`, `mount`) and read-only path checks | Confirm management IP, VLAN, uplink/aggregation, storage protocols, dependent hosts and routes. No scrub, mount/unmount, storage test or bulk transfer. |
| Monitoring | Uptime Kuma monitor list, Prometheus targets, Grafana dashboards/alerts, Loki/syslog ingestion | Passive inspection. Record which checks are independent of the gateway and can prove recovery. Avoid alert test sends during discovery. |

For each observation record date/time, target, command or UI path, redacted result, confidence, and unresolved contradiction in `docs/udm-pro-max-migration.md` or a linked dated note. Use a representative client in each subnet for later **authorized** functional tests; passive configuration inspection alone cannot prove firewall behavior. Simple DNS lookups and connection probes may generate logs or touch services; agree endpoints/rate before testing. Do not run scans or traffic generators as part of this baseline.

Cross-check gateway dependencies in DHCP option 3/6/15/42/43, DNS forwarding and redirects, reverse proxy upstreams, VPN peers, static routes, monitoring targets, syslog, NTP, mDNS reflection, AP inform records, NAS mounts and application allowlists. Document whether IPv6 is disabled, delegated, routed or filtered on every segment; absence from IPv4 rules is not an IPv6 policy.
